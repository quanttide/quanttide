# meta-align

用元工程的元认知骨架，判断其他领域的结构与表述。

## 上游（先读，不凭记忆）

| 文件 | 作用 |
|:--|:--|
| `domains/quanttide-meta/data/profile/README.md` | 元认知快照的定位：快照式，只放当前最新 |
| `domains/quanttide-meta/data/profile/quanttide-think/cogitive-model.md` | 骨架：六个范畴、四个层级、四条关系与各条约束 |
| `domains/quanttide-meta/data/profile/quanttide-founder/think.md` | 骨架的部署示范：类名对照、规模、缺口怎么记 |
| `domains/quanttide-meta/data/profile/quanttide-agent/` | 智能体一侧的档案 |
| `domains/quanttide-meta/data/profile/quanttide-relation/` | 主体之间关系的档案 |

## 使用场景

- 在任一领域（`domains/quanttide-*`）新增或改造日志、档案、本体、路线图
- 把素材从一个领域移到另一个领域
- 两个领域对同一件事出现两种说法

## 判断三条

1. **归类**：待判断的条目落进骨架的哪一格——情境、中介、办法、二阶、归宿、反向；落在哪一格要给出处
2. **关系**：条目之间的连接是否是骨架的四条——触发、应对、服务于、排除；出现第五条，先问是骨架缺一条，还是这里在自造
3. **层级**：该领域有没有自己的层级说法与骨架冲突

## 规则

- 类名可以本地化（触发点／创作困境），**范畴不许增删**；增删即改骨架，须回元工程层决策，不在本领域私下改
- 四条关系的语义跨领域必须一致；不一致处写成对照，不留两套说法
- 分类为了**可追溯**，不为**分家**：素材可以带域标签，但要能放进同一张图对照
- 判断结论要落成可核对的句子并带出处，不能是"感觉不对"
- 缺格先判"数据未提取"，再判"框架缺格"（见 QCM 的跨集一致性）

## 工作流

### 1. 读上游

读上表五处，以仓内现状为准确认骨架的当前版本（快照式，不引用记忆里的旧版本）。

### 2. 取样本

从待判断领域取三类样本：日志条目、档案条目、该领域自己的本体或结构文档。

### 3. 逐条归类与连边

把样本按骨架的格归类、按四条关系连边，落成一张对照表（样本 → 格 → 关系 → 出处）。

### 4. 出判断

三类结论分开放：一致、可本地化（类名不同而位置相同）、不一致（须回元工程层）。
每一条写成可核对的句子，带文件与出处。

### 5. 落点

- 骨架层的问题 → 回 `domains/quanttide-meta/data/profile`（替换式更新，写清取代了什么）
- 领域自身的问题 → 在该领域内修，但用骨架的格与关系表述
- 跨领域的不一致 → 落 `domains/quanttide-meta/data/insight`，带出处

## 坑（实测）

- **别把缺格当差异**：先查是不是提取粒度问题
- **快照式不等于可随意覆盖**：替换时写清取代了什么
- **跨域搬运前先定判据再搬**：按内容归属分，不按仓库方便分
- **元认知只在 meta 层增删**：领域侧只能换类名，不能改范畴数
