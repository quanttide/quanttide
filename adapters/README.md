# 量潮适配

量潮适配库（适配轴），承接「领域 → 适配 → 应用」的中间层。每个子目录对应一个独立适配仓库（子模块）。

## 定位

适配轴是量潮第二大脑的第四条轴，与另外三条轴正交：

| 轴 | 路径 | 回答的问题 |
|----|------|-----------|
| 能力轴 | `assets/` | 我如何运行 |
| 领域轴 | `domains/` | 我关心什么 |
| 主体轴 | `default/` | 我是谁 |
| **适配轴** | `adapters/` | **我如何被接通** |

适配轴站在领域与应用之间，把 `domains/` 的知识转换成 `apps/` 与平台可消费的形态。它不生产知识，只做接通。

## 职责边界

适配器是转换器，不是事实源：

- **归适配轴**：协议转换、格式映射、接口包装、运行时桥接、外部系统对接
- **不归适配轴**：领域概念与事实定义（`domains/`）、可部署应用（`apps/`）、工程标准与规范（`assets/`）

领域定义"是什么"，适配定义"怎么接上"。一个领域可以接多个适配器；一个适配器不应重复定义领域事实。

## 目录结构

```
adapters/
└── quanttide-feishu/        # 飞书适配
```

每个适配器按 `adapters/{name}` 建独立仓库（子模块），落地后在本文件登记。

## 命名规则

- 目录名小写，遵循仓库统一命名规范
- 适配器名自描述被适配对象，避免与领域仓库同名造成职责混淆
- 已落地：`quanttide-feishu`（被适配对象 = 飞书），目录名与仓库名一致
