## 接入约定

1. 每个法人主体对应一个独立仓库，路径 `defaults/quanttide-{name}`
2. 仓库包含独立的 README、LICENSE、CHANGELOG 等档案文件
3. 接入后同步更新本文件的主体清单

## 主体分离原则

**顶层依据：能开源的全部开源，开源资产由联盟托管；闭源部分商业化；商业化的产出不断回流开源，升级整个体系。**联盟是公共底料的存放地，公司是商业化的前沿；一份资产的归属取决于它当前开闭状态，今天的闭源可能是明天的开源。

每个主体的档案只回答属于它自己的问题：

- **公司**：谁用人、谁负责——用人制度、经营报表、治理效力文件
- **联盟**：谁培养、谁组织——选拔组织、培养机制、对外宣传、工作日志
- **实训基地**：教学与培养的运作档案；**创始人**：个人创业档案

已确认口径（招聘，2026-10）：**公司是招聘单位；联盟托管公司的招聘需求，依托实训基地组织选拔；候选人加入的是公司。**

这条原则解决的不只是文档存放，而是经营负担：文档两属时，每份材料的归属都在暗中等经营者裁决；归属单一后，档案替他把裁决做在架构里。因此新内容入库前必须先回答归属，两属即报告。

判定次序：

1. **效力文件看效力来源**：经公司代表大会批准、审计委员会解释的章程留公司，引用可以跨主体
2. **活动记录看活动由谁组织**：选拔组织、培养过程的记录归联盟
3. **对外宣传看谁对外发声**：解释「怎么选拔」的宣传归联盟，商业宣传归公司
4. **混合服务按付费属性切分**：同一服务内免费与付费并存的，不按职能整体归属；免费/付费是主要边界，切分线由用户裁定（如 qtclass）
