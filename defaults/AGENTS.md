# AGENTS 工作指南 - defaults/

本文件指导 Agent 在 `defaults/`（主体轴）下工作。主体分离原则见 [README.md](./README.md)，接入与维护约定见 [CONTRIBUTING.md](./CONTRIBUTING.md)，当前快照见 [STATUS.md](./STATUS.md)。

## 核心判断：归属三问

新增或移动任何内容前，先回答归属：

1. **谁用人、谁负责？** → 公司（quanttide-tech）：用人制度、经营报表、治理效力文件、应用内功能数据
2. **谁培养、谁组织？** → 联盟（quanttide-alliance）：选拔组织、培养机制、招聘宣传、工作日志、方法论洞察
3. **效力文件看效力来源**：经公司治理机构审议的章程留公司，引用可以跨主体，不因内容涉及联盟职能而搬家
4. **服务看付费属性**：qtclass 一类的商业服务整体归公司；服务内免费与付费并存的，**免费/付费是主要边界**，切分线由用户画，Agent 不得按「培养/商业」自行外推归属

**两属即报告，不擅自拆文件**：一份文档同时命中两类归属时，停下来向用户报告，等待口径裁决。口径归用户，Agent 不自创。**已确认的口径只覆盖已裁决的对象**：qtclass 的归属未经裁决，不得类推适用招聘侧的口径。

## 迁移纪律

执行跨主体迁移时，逐条执行：

1. **先定口径再平移**：迁移方案向用户对齐后才动手；「呈现对齐方案」不等于已授权
2. **只移动不改写**：平移不改一个字；需要改写口径的，作为单独一轮
3. **入仓前脱敏**：人员信息（人名、部门名、人名称谓如「刘秘」）与部署敏感（域名、桶名、账号、密钥）一律移除或改写
4. **缺类目仓时建仓**：命名机械套用 `{类型}-of-{主体}`（如 `quanttide-handbook-of-innovation-alliance`），scaffold（LICENSE/README/CHANGELOG）照 academy 同类仓体例；建新远端仓前须用户点头
5. **状态入 ROADMAP**：内容待梳理、形态不完整的，在该仓 ROADMAP 写明状态与下一步，不留空文件占位
6. **命名归用户**：发现目录名拼写错误、名不副实，只报告，不自行改名
7. **分层提交**：内容仓 → 主体主仓（子模块指针）→ 根仓库，每层提交推送后再进上一层
8. **删除前查引用**：README、索引、代码引用逐个确认；应用内被代码按固定路径引用的数据属于代码重构，不是平移

## 提交约定

- 遵循 Conventional Commits：`docs:` 内容变更、`chore:` 子模块指针、`fix:` 拼写修正
- 主体主仓的 CHANGELOG 记子模块变更，内容仓的 CHANGELOG 记内容变更，两层都留痕
- 远端有新提交时 `git pull --rebase` 后重推，不覆盖他线工作
